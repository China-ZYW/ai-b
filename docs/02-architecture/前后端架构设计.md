## 一、文档说明

### 1.1 目的

将可行性报告中的产品与技术方案，落地为**可直接指导编码**的前后端架构设计，明确工程结构、分层职责、核心流程、接口契约与部署方式。

### 1.2 设计约束（关键前提）

| 约束 | 说明 | 对架构的影响 |
|------|------|------------|
| **单台 4核4G** | 内存紧张 | 采用**模块化单体**，不拆微服务；不常驻 Kafka/监控栈/Python 服务 |
| **单人开发** | 精力有限 | 优先成熟框架、约定优于配置、减少运维组件 |
| **数据不出用户环境** | 安全底线 | 只读账号、SQL 白名单、结果不落地 |
| **成本敏感** | LLM 是主要可变成本 | 多层缓存、Prompt 缓存、并发护栏 |
| **可演进** | 用户量增长后需扩展 | 无状态设计、适配器/抽象层，预留拆分点 |

### 1.3 架构决策记录（ADR 摘要）

| 决策点 | 选择 | 理由 | 放弃的方案 |
|--------|------|------|-----------|
| 应用形态 | **模块化单体**（单 Spring Boot） | 4核4G + 单人，运维最简 | 微服务（内存/复杂度不够） |
| NL2SQL 实现 | **Java 内直接调 LLM** | 省 ~400MB，避免跨语言 | 独立 Python/FastAPI（P1 再拆） |
| 异步任务 | **Redis Stream + @Async** | 轻量、已在栈内 | Kafka（>1000 用户再上） |
| 消息/缓存 | **Redis 7** 一体多用 | 缓存+队列+会话+限流 | 独立 MQ |
| 定时任务 | **Spring @Scheduled** | 单实例足够 | XXL-Job（多实例再上） |
| 文件存储 | **本地磁盘（bind mount）** | MVP 够用 | MinIO/OSS（多节点再上） |
| 前端框架 | **Vue3 + TS + Vite** | 生态成熟、上手快 | React（团队更熟 Vue） |
| 图表 | **Apache ECharts** | 大屏能力强、中文文档好 | AntV/Chart.js |
| 流式返回 | **SSE** | 问数分步反馈，比 WebSocket 轻 | WebSocket（无需双向） |

### 1.4 术语表

| 术语 | 含义 |
|------|------|
| NL2SQL | 自然语言转 SQL |
| Schema Linking | 从整库中筛出与问题相关的表/字段 |
| 数据源适配器 | 屏蔽不同数据库差异的统一接口 |
| 少样本库 | 历史正确问答对，用于 Few-shot 提升准确率 |
| MRR | 月度经常性收入 |

### 2.2 分层职责

| 层 | 职责 | 关键约束 |
|----|------|---------|
| 前端（Vue3 SPA） | 交互、可视化渲染、对话流展示 | 不含业务逻辑，只做展示与编排调用 |

| Service | 业务编排、事务、领域规则 | 模块化，跨模块通过接口调用 |

| Mapper | 持久化（MyBatis-Plus） | 仅元数据库，不含用户业务数据 |
| 中间件 | MySQL/Redis/磁盘/LLM | 无状态服务，状态外置到 Redis |

### 2.4 核心请求链路（AI 问数）

```
浏览器 → Nginx → ChatController(SSE)
  → ChatService.ask()
    → ① 加载 Schema（Redis 缓存 / MySQL 元数据）
    → ② SchemaLinker 选相关表字段
    → ③ PromptBuilder 组装（含少样本）
    → ④ LlmClient 调 DeepSeek（temperature=0）
    → ⑤ SqlValidator（JSqlParser：仅 SELECT / 表字段存在 / 注入 LIMIT）
    → ⑥ DataSourceAdapter 在用户库执行（超时30s，≤1万行，信号量≤5）
        ├─ 成功 → ⑦ ChartRecommender 选图表 → 写 query_history → 返回
        └─ 失败 → ⑧ 带错误回喂 LLM，重试≤2 次
  → SSE 分步推送：sql → executing → result / error
```

### 3.2 分层与依赖规则

| 规则 | 说明 |
|------|------|
| 单向依赖 | controller → service → mapper；禁止反向 |
| 跨模块调用 | 只能通过对方 `service` 接口，禁止直接访问他人 mapper |
| DTO 隔离 | entity 不出 controller，统一用 DTO/VO |
| 事务边界 | 只在 service 层用 `@Transactional` |
| 无状态 | 不在服务内保存会话态，全部入 Redis |

### 3.4 认证与安全

| 项 | 设计 |
|----|------|
| 认证方式 | JWT（Access Token 2h + Refresh Token 7d，存 Redis 白名单/黑名单） |
| 密码存储 | BCrypt |
| 传输 | 全站 HTTPS（Nginx + Let's Encrypt） |
| 鉴权 | Spring Security 过滤器链 + `@PreAuthorize`；`UserContext`（ThreadLocal）承载当前用户 |
| 数据源凭证 | AES-GCM 加密存 `data_source.config`，密钥来自环境变量 |

```java
// common/security/JwtAuthFilter.java（示意）
public class JwtAuthFilter extends OncePerRequestFilter {
    protected void doFilterInternal(req, resp, chain) {
        String token = resolveToken(req);            // Authorization: Bearer xxx
        if (token != null && jwtProvider.validate(token)) {
            UserContext.set(jwtProvider.parse(token));
        }
        chain.doFilter(req, resp);
    }
}
```

### 3.6 NL2SQL 引擎（核心）

**组件划分**：

| 组件 | 职责 | 关键点 |
|------|------|--------|
| `IntentClassifier` | 意图分类（简单/聚合/对比/趋势/明细） | 规则 + LLM，选不同 Prompt 模板 |
| `SchemaLinker` | 选相关表/字段 | 同义词典 + 关键词 + 历史频次 + (可选)LLM 预筛 |
| `PromptBuilder` | 组装 Prompt | 相关表结构 + 少样本 + 方言 + 业务规则 + 只输出 SQL |
| `LlmClient` | 调 LLM | 默认 DeepSeek，复杂降级通义；temperature=0；HTTP 直连 |
| `SqlValidator` | 静态校验 | JSqlParser：仅 SELECT、表字段存在、注入 LIMIT、禁多表笛卡尔 |
| `SqlRepairer` | 执行反馈修正 | 报错回喂 LLM，重试 ≤2 |
| `FewShotStore` | 少样本库 | 从 `query_history(is_correct=1)` 取相似问答 |

```java
// module/chat/nl2sql/Nl2SqlEngine.java（编排示意）
public Nl2SqlResult generate(Long dsId, String question, String convId) {
    Schema schema = schemaCache.get(dsId);                 // ① Redis 缓存
    Intent intent = intentClassifier.classify(question);   // ②
    SchemaSlice slice = schemaLinker.link(schema, question);// ③ 相关表/字段
    List<FewShot> shots = fewShotStore.similar(dsId, question, 4);
    String prompt = promptBuilder.build(slice, intent, shots, question); // ④
    String sql = llmClient.complete(prompt, intent.model()); // ⑤
    sql = sqlValidator.validateAndNormalize(sql, schema);    // ⑥ 仅SELECT+LIMIT
    return new Nl2SqlResult(sql, intent, slice);
}
```

### 3.8 缓存设计（Redis）

| Key 模式 | 内容 | TTL | 说明 |
|---------|------|-----|------|
| `schema:{dsId}` | 表/字段元数据 | 30min | 元数据扫描后写入 |
| `query:result:{sqlHash}` | 查询结果 | 5min | 相同 SQL 直接命中 |
| `llm:resp:{promptHash}` | LLM 响应 | 1h | 降 LLM 成本 |
| `user:token:{uid}` | 会话/Refresh | 7d | 无状态鉴权 |
| `rate:free:{uid}` | 免费版问数计数 | 1d | 20 次/天限流 |
| `lock:meta:{dsId}` | 元数据同步锁 | 60s | 防并发扫描 |

```ts
router.beforeEach((to) => {
  const user = useUserStore();
  if (to.meta.public) return true;
  if (!user.token) return { path: '/login', query: { redirect: to.fullPath } };
  return true;
});
```

### 4.6 流式响应（SSE）封装

```ts
// composables/useSSE.ts
export function askStream(payload: ChatQuery, handlers: {
  onSql: (sql: string) => void;
  onResult: (r: QueryResult) => void;
  onError: (e: string) => void;
}) {
  const es = new EventSource(`/api/chat/query/stream?${qs(payload)}`);
  es.addEventListener('sql',     (e) => handlers.onSql(JSON.parse(e.data)));
  es.addEventListener('result',  (e) => { handlers.onResult(JSON.parse(e.data)); es.close(); });
  es.addEventListener('error',   (e) => { handlers.onError(e.data); es.close(); });
  return es;
}
```
